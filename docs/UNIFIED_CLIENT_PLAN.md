# StrmAction 四端统一方案（2026-10-24）

状态：产品选择已确定；本文件为实施方案与验收标准，尚未修改两个仓库的业务代码。

用户已确定的范围：Android、iOS、Windows、macOS 共用一个 Flutter 客户端；媒体库页面继续复用云端 Web；首版保留现有画中画、后台播放、Android TV 遥控、音轨字幕、请求头与缓存能力。普通浏览器不新增网页播放器。

补充硬约束：四个平台的客户端均在 CI 完成检查、Release 构建、打包和产物上传。用户本地只需编辑源码、提交和下载安装包，不需要安装或下载 Flutter、Android、Xcode 或 Windows 构建 SDK；后续实施也不在用户电脑上下载这些 SDK 来验证。需要 SDK 的生成、依赖解析、分析、测试和编译均交由 CI 执行。

## 产品规则

| 事项 | 已确定规则 |
|---|---|
| 播放选项 | 对外只保留“内部播放”“复制链接”；移除外部播放器唤起、intent、Infuse/VLC 入口与外部回退 |
| 普通浏览器 | 内部播放不可用，说明需使用 App；保留复制链接能力，不暗中唤起外部播放器 |
| 方式优先级 | 设备显式覆盖 > 当前账号默认 > 云端全局默认；新的全局默认建议为内部播放 |
| 设备覆盖归属 | 按服务器和账号隔离播放方式覆盖，避免共享设备换账号后沿用另一账号的选择 |
| 自动连播 | 电视剧跳过已看与不可播放集；保留现有跨季连续播放能力 |
| 手动上下集 | 按可播放列表中的相邻条目切换，不因已看而跳过 |
| 课程 / 家庭视频 | 按自然顺序连续播放，不因已看而跳课；网页、起播和播放器共用排序规则 |
| 连播提示 | 建议统一为 5 秒、允许取消或立即播放；属于可调整的界面默认值 |
| 已看阈值 | 保留现有 90% 规则，统一比较边界；进度传输使用毫秒 |
| 缓存优先级 | 设备显式覆盖 > 云端显式默认 > 平台出厂预算；迁移首版保留各端原有出厂预算 |
| 缓存语义 | 明确区分预读容量与磁盘容量；仅保留当前视频缓存，退出播放清空；切集清理上一集 |
| 证书信任 | 公共 CA 正常验证；私有站点导入私有 CA，同样校验证书链与主机名；四端统一规则 |
| 最低系统 | Android 7 / API 24；iOS 16；Windows 10；macOS 12 |
| 升级 | 保留应用标识，迁移服务器地址、已导入 CA 和可转换的本地设置；允许重新登录 |
| 代码归属 | 统一客户端放在 strmaction 仓库；原 iOS 仓库保留历史，迁移验收后停止独立开发 |
| 分发 | 延续 APK、IPA 安装包；Windows/macOS 保留现有构建产物 |
| 构建位置 | 四端统一由 GitHub Actions 构建，SDK 只安装在 CI runner 上 |

“使用账号默认”“使用云端默认”采用独立的继承开关，不作为第三种播放模式出现在选择列表。

播放失败固定提供重试、复制链接、返回等明确动作；旧 fallback_on_error 开关随外部回退逻辑一起清理，避免继续提供没有效果的设置。复制动作使用用户所选媒体版本的真实直链，不复制播放进度凭证。

## 技术方案

在 strmaction 中将现有 desktop_flutter 逐步演进为 client_flutter。复用已有 Dart 播放器抽屉、控件、模型和测试；补齐移动端布局、触摸手势、平台目录、设备生命周期及系统服务适配。

```text
云后端 + 云 Web
        │
        ▼
client_flutter（Android / iOS / Windows / macOS）
  ├─ WebView 与统一桥接
  ├─ 服务器配置、账号 / 设备偏好、证书管理界面
  ├─ 播放参数、进度同步、排序与连播调度
  ├─ Flutter 播放控件与平台布局
  └─ PlayerEngine / Trust / Cache 平台适配
       ├─ Android：Media3 + 既有缓存能力
       ├─ iOS：KSPlayer + 既有本地缓存与信任能力
       └─ Windows / macOS：media_kit
```

首版统一 Flutter 界面、业务规则与接口，保留已验证的播放内核。Flutter 不要求所有平台使用相同内核。是否进一步统一到 media_kit，由同一组真机功能与片源检查决定，不作为本次迁移成功的前提。

共用 Dart 层负责发起播放、解析响应、可靠进度队列与自动连播。平台内核负责媒体渲染、解码、系统画中画 / 后台通道及缓存读写。迁移时关闭被替换的旧进度计时器，避免原生与 Dart 重复上报。

平台间共享的是证书信任规则和证书数据模型；WebView、API、字幕和媒体网络通道分别接入该规则，不能只修改健康检查或 API 的 TLS 行为。需要覆盖初始地址、302 后地址以及字幕 / 分片请求。

现有 desktop_flutter 的窗口初始化、文件路径、键盘和关闭事件以桌面为前提，需先通过平台边界隔离，再加入移动平台；不能仅生成 Android / iOS 工程目录后直接发布。

## 接口与旧数据迁移

1. 对外可选模式收敛为两种。已有内部模式别名、auto、外部播放器模式按兼容表归入内部播放；已有 copy 保留为复制链接。旧字段先兼容读取，设置页不再提供旧值。
2. 新桥接传递条目 ID、所选 media_file_id 和必要的设备覆盖。原生侧请求播放信息并执行实际模式。迁移期间保留旧桥接入口，避免新网页立即破坏尚未升级的安装包。
3. 明确区分自动连播目标与手动相邻目标。自动目标为空表示停止，不允许客户端再用相邻条目代替。所有目标从有效、未删除、存在可播放媒体的序列计算。
4. 长列表保留完整索引关系；如做分页则按条目 ID 定位，不能截断列表后沿用原索引。
5. 新增明确的预读 / 磁盘设置及来源状态。旧 cache_limit_mb 的转换按原平台含义处理，不把内存预算误当磁盘容量。
6. 迁移原 Android SharedPreferences、iOS UserDefaults 和桌面 config.json 中的服务器及可用设置；保留既有 applicationId / bundle identifier，并沿用原升级签名身份。
7. iOS 已导入的 CA 可以迁移。旧 Android / 桌面“允许自签名”布尔开关没有证书内容，不能转换成 CA；升级引导应明确提示使用此类站点的用户导入根 CA，不自动信任未知证书。

| 2. 共用客户端基础 | 演进 desktop_flutter，隔离桌面 API，统一模型、偏好、进度队列、设置来源、桥接 | CI 构建的桌面版本、Dart 公共逻辑、关闭 / 暂停 / 失败重试检查 |
| 3. Android 接入 | Flutter 壳与控件、Media3 适配、遥控焦点、PiP、后台、私有 CA 与缓存 | CI 构建的 APK、手机与 Android TV 验收记录 |
| 4. iOS 接入 | Flutter 壳与控件、KSPlayer 适配、PiP / 后台、证书与缓存迁移 | CI 构建的 IPA、iPhone / iPad 验收记录 |
| 5. 四端联合验收 | 参数、模式、进度、连播、缓存、TLS、升级与打包一致性 | 四端功能矩阵、安装包、构建步骤、迁移说明 |
| 6. 旧客户端收尾 | 新版本通过验收后更新仓库入口、构建和维护说明 | strmaction 为统一维护入口；旧 iOS 仓库保留历史 |

阶段 3 / 4 可依据设备可用情况调整先后；不在本方案中承诺未经验证的工期。

## CI 构建与交付

现状检查：strmaction 的 `.github/workflows/desktop-flutter.yml` 已有 Windows / macOS 的 Flutter 构建、测试与产物上传；strmaction-ios 的 `.github/workflows/build.yml` 已有原生 iOS 构建和未签名 IPA 打包；strmaction 当前没有 Android 构建 workflow。现有流水线使用 floating stable / latest 等环境，需在实施中锁定经验证的 Flutter、JDK、构建工具与 runner 镜像组合。

| 构建目标 | CI 环境 | 必须上传的主要产物 |
|---|---|---|
| Android 手机 / Android TV | Linux runner，配置 Flutter、JDK、Android SDK / NDK | APK；需要时按 ABI 另提供安装包；正式升级包沿用原签名身份 |
| iPhone / iPad | macOS runner，配置 Flutter、Xcode、原生依赖工具 | IPA，必要的归档 / 符号及签名状态说明 |
| Windows | Windows runner，配置 Flutter、Visual Studio C++ 工具链、NuGet | 含 exe、DLL 与资源的完整 ZIP，不能只上传 exe |
| macOS | macOS runner，配置 Flutter、Xcode 与原生依赖工具 | 包含完整 .app 的 ZIP；配置发布签名时同时完成相应签名流程 |

流水线规则：

- 对公共 Dart 代码、平台工程、Web 桥接、相关契约或 workflow 的修改，触发所有受影响平台的构建；公共客户端修改必须验证四端，不能只运行 analyze / test 代替原生编译。
- 支持 PR、相关代码 push 和 `workflow_dispatch`。推送版本 tag 时收集同一提交的四端产物发布到 Release；普通构建从 Actions 下载 Artifacts。
- 用质量检查 job 运行后端回归、Web 类型检查 / 生产构建和 Flutter 分析 / 单元测试；平台构建 job 编译真实 Release 应用并验证产物存在。
- 配置依赖缓存、并发取消过期构建、合理超时、产物保留时间、缺失产物报错；失败时保留诊断日志。固定版本号和 build number 的生成规则，记录提交 SHA 与构建环境。
- 原生插件、平台工程及必要生成配置纳入版本管理。可重复的生成步骤可以在 CI 执行，不要求用户本地执行 flutter create、Gradle wrapper、XcodeGen 或 SDK 生成命令。
- 正式签名材料通过 GitHub Secrets 注入 CI。Android 使用原有 keystore；不能为了让 CI 变绿而换成新签名身份。未配置发布密钥时，测试包与未签名产物应清楚标记，不能冒充可覆盖升级的正式包。
- iOS 首版延续现有未签名 IPA 交付方式，下载后通过既有重签 / 安装链路使用。若配置证书和描述文件，则在 CI 另生成符合该分发方式的已签名 IPA；未签名 IPA 不视为可直接安装的签名包。
- 构建通过与设备验收分开记录：CI 必须证明编译和打包成功；画中画、后台、电视操作和真实片源兼容性仍通过下载安装包在设备上验证，用户不承担本地编译步骤。

进入“迁移完成”状态前，需提供同一提交的四端成功构建记录和实际下载地址。仅提交 workflow 文件、仅有绿色检查或仅生成本地产物均不满足交付要求。

## 验收标准

- 云设置、个人设置和四端界面只出现内部播放、复制链接两种播放模式；外部播放器跳转全部移除。复制的是所选版本的直链。
- 账号默认、本机覆盖、清除覆盖、切换账号和切换服务器行为正确；普通浏览器不尝试内部播放或外部唤起。
- 同一媒体版本在四端请求中对应同一 media_file_id；进度、字幕和媒体参数归属正确账号及条目。
- 暂停、后台、退出、切集与结束均写入正确快照；HTTP 500 / 临时断网不会丢失待发记录；凭证失效停止对应会话重试并提示恢复操作。
- 自动连播跳过已看与不可播放集；全部后续集已看时停止。手动上下集仍按相邻顺序。课程 1、2、10 排序正确；205 集及更长列表不越界。
- 内封音轨、内封字幕、外挂字幕均可枚举与切换；已支持的格式、请求头和重定向播放能力通过同样片源检查。
- 手机 PiP、后台播放、系统媒体控制、横竖屏、长按倍速与手势可用；Android TV 遥控焦点、返回和选集可用；桌面键盘与窗口操作可用。
- 云缓存默认和设备覆盖可观察生效；退出播放清理本视频缓存；不同内核的实际内存占用与磁盘预算分别验证。
- WebView、API、字幕、媒体和重定向后的 TLS 行为遵循同一 CA 策略；主机名错误或未知 CA 被拒绝，正确导入 CA 后可连接。
- 原应用可按相同应用标识和签名身份升级，服务器 / CA / 可迁移设置保留，必要时重新登录；生成可检查的 APK、IPA 和桌面产物。
- 从无本地客户端 SDK 的工作环境提交代码后，可在 CI 获取同一提交的 Android APK、iOS IPA、Windows ZIP、macOS ZIP；四个构建 job 均成功，产物可下载且签名状态明确。
