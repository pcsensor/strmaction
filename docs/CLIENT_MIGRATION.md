# 统一客户端实施与验收

本次代码在 `codex/unified-client` 分支实施。媒体库继续使用云端 Web，四个平台共用 `client_flutter/` 的设置、桥接、播放器控件和进度队列；移动端保留 Media3 / KSPlayer 的原生播放与系统服务。

## 构建和安装

[Clients CI](https://github.com/pcsensor/strmaction/actions/workflows/clients.yml) 在 push、PR 和手动触发时运行。检查包含后端回归、Web 类型检查与生产构建、Flutter 分析与公共测试、Android 原生信任 / 重定向测试。四端构建均成功后，汇总 job 才成功。

| Artifact | 内容 | 签名状态 |
|---|---|---|
| StrmAction-Android | 已签名 Release APK、测试 APK | Release 使用固定的新发布密钥；缺少全部签名配置时才输出 unsigned |
| StrmAction-iOS | 未签名 IPA | 下载后使用既有重签安装工具 |
| StrmAction-windows | exe、DLL、资源完整 ZIP | 未签名 |
| StrmAction-macos | 完整 .app ZIP | ad hoc；尚未做 Developer ID 公证 |

每个包附 `build-info.json`，记录提交、CI 运行、工具链与签名状态，并列出包的 SHA-256。Artifacts 保留 30 天。用户本地不需要 Flutter、Android、Xcode、Windows SDK，源码生成和编译都在 runner 完成。

工具链固定 Flutter 3.47.0 / Dart 3.13；Android 使用 JDK 17、AGP 8.11.1、Kotlin 2.2.20、Gradle 8.14，保持与稳定版 WebView 插件兼容；iOS KSPlayer 固定 2.3.4。Windows 稳定版 WebView 插件缺少原生证书挑战派发，CI 应用仓库内的小范围 WebView2 回调补丁；默认拒绝，只有共享严格验证回调通过才接受，并清除会话中的证书例外缓存。最低系统为 Android 7、iOS 16、Windows 10、macOS 12。

用户已于 2026-10-24 明确选择重新生成 Android 正式发布密钥，不再沿用旧密钥。新密钥为 RSA 3072 位，PKCS#12 格式，别名 `strmaction`，证书有效期至 2054-03-11。私钥和密码备份在 Git 仓库之外，并注入 Actions Secrets；仓库只保存公开证书 [android-release-certificate.pem](../ci/android-release-certificate.pem)。

证书 SHA-256：`7a70bea533a5a3d0c3e91f0ce9412926f6349df4263db77713b48804281248b0`。CI 对最终 Release APK 运行 `apksigner verify`，要求签名与该公开证书一致，`build-info.json` 也记录此指纹。下载安装时选择 `StrmAction-Android.apk`；测试 APK 仍使用独立测试签名。

同一包名的旧签名版或测试版不能被新正式签名覆盖，首次切换需要卸载旧版，卸载会清除沙盒设置；新正式版之间继续用这套固定密钥升级。重新生成密钥不提供旧版设置自动迁移保证。

仓库 Actions Secrets 使用 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。全部缺失时生成明确标记的未签名 Release，部分缺失则报错；CI 不会每次生成新发布密钥。请另行妥善保存仓库外的密钥和密码备份，GitHub Secrets 无法回读导出。

## 设置和行为

- **播放模式**：本机按服务器 + 账号保存的覆盖 → 账号默认 → 全局默认。公开选项仅内部播放与复制链接；旧模式归一化到内部播放。普通浏览器内部播放禁用，明确提示使用 App。
- **媒体版本**：Web 选中的 `media_file_id` 经共享桥接传到播放 API，字幕下载同样绑定该版本；复制链接返回该版本的直链。
- **连播**：自动连播只使用服务端 `next_item_id`，跳过已看、缺失、删除、无有效媒体的集数；手动上下集按相邻可播放顺序。课程 / 家庭视频按 Web 自然顺序，不跳过已看课程。
- **进度**：暂停、后台、seek、结束、关闭、切集补报；退出先冻结播放、发送最终快照，再释放引擎。发送前持久化，确认后移除；失败在下次启动恢复，失效凭证停止重试。关闭播放器后触发 Web 进度刷新事件。
- **缓存**：设备覆盖 → 云默认 → 平台原预算。默认预读 Android 512 MB、iOS / 桌面 128 MB；磁盘预算 2048 MB。0 分别关闭预读或落盘；只保留当前视频，切集 / 退出删除。Android 使用原 Media3 LRU；iOS 使用原字节范围缓存；桌面使用有硬容量上限的字节块 LRU，避免 mpv 追加文件无限增长。范围缓存适用于支持 HTTP Range 的渐进媒体；桌面 HLS / DASH 或不支持 Range 的来源使用原生流式传输与内存缓冲；iOS 继承原有渐进媒体缓存链路，HLS / DASH 兼容性需另按片源验证，不能宣称所有格式都落盘。
- **TLS**：设置中导入自签名根 CA（PEM，支持多根），API / 媒体保持证书链与主机名校验。WebView 的私有证书挑战还要与独立严格 TLS 连接的证书一致才能接受。旧“允许自签名”布尔开关不再放行任何证书。

## 升级迁移

Android / iOS applicationId 与 bundle identifier 均保留 `top.strmaction.companion`；桌面身份和配置目录保留。允许重新登录。Android 从原 SharedPreferences、iOS 从 UserDefaults 迁移服务器和本地预算，iOS 原 CA 根信任库一并迁移。

迁移与覆盖安装依赖相同的签名身份；本次 Android 已选择更换发布密钥，旧安装必须卸载，因此不能自动保留其沙盒数据。iOS 和桌面的迁移仍应在相同身份的升级包上验证。旧 Android / 桌面的“信任任意证书”开关没有证书内容，不能迁移为 CA；私有站点需导入对应根 CA。

原 `strmaction-ios` 仓库保持历史与独立构建。此次仅将所需原生核心导入主仓库，完成真机迁移验收后再停止独立开发，不提前归档。

## 2.0.2 锁定与 iOS 再次播放修复

- 锁定图标跟随控件可见状态：3.5 秒自动隐藏，单击画面唤起 / 隐藏，锁定暂停时也会自动隐藏；仅展示解锁入口，不开放被锁定的播放手势。
- iOS 每次播放使用独立会话标识，原生画面、异步加载、状态回调和释放命令均校验所属会话，防止退出后旧视图重建已关闭的缓存地址。
- 同一片源的缓存目录也按会话唯一分配；旧会话重复 / 延迟清理不影响新会话，取消的监听与加载会回收自身目录。
- 播放准备完成、缓冲恢复或画面进度继续时清除历史错误；Flutter 自动撤下已恢复播放的错误提示。错误提示新增关闭按钮，关闭不触发重试、返回或暂停；真正的新错误仍会显示。
- CI 增加原生缓存目录的同源重入、延迟清理及重复释放检查，以及移动端锁定、错误恢复 / 关闭和跨会话事件回归。版本 `2.0.2+22`，沿用现有正式签名，无需额外更新云端。

真机重点复验：开始播放 → 返回媒体库 → 再次播放同一视频，重复数次；锁定后自动隐藏、单击唤起 / 隐藏并解锁；真正无法打开的片源仍能提示失败和重试。

## 2.0.4 播放器退出修复

- 原退出流程先设置“正在关闭”，随后依次等待暂停、进度补报、引擎释放和窗口恢复。暂停 / 释放异常或移动端窗口恢复异常会中断页面关闭，后续点击又被“正在关闭”拦截；原生调用不返回也会一直等待。这一缺陷可在不涉及网络的回归用例中复现。
- Android、iOS、Windows、macOS 共用该流程，均有暂停 / 释放异常导致无法退出的风险。移动端恢复系统栏 / 方向的异常原来也未捕获；桌面已有窗口异常兜底，但同样缺少等待上限。旧版 `companion/` 的左上角按钮直接结束 Activity，不走这条 Flutter 退出链。
- 公共退出逻辑现在逐步捕获并记录清理异常，暂停、释放和窗口恢复各设 3 秒等待上限，最后执行页面关闭。最终进度仍沿用持久化和限时补报；关闭与切集复用同一个清理任务，迟到的加载 / 播放状态不再重启进度上报。
- 新增 36 个四平台页面退出用例，覆盖左上角实际点击、正常退出、暂停 / 释放 / 窗口恢复异常与不返回、重复点击、系统返回、切集及迟到加载。已验证原代码的暂停异常用例失败、修复后通过；平台变体测试使用模拟引擎 / 通道，实际设备仍需复验。
- 版本 `2.0.4+24`，客户端显示版本与安装包版本同步，沿用现有 Android 正式签名。

## 2.0.5 并发分段的播放缺口修复

- 保留并发 Range 分段，策略初始 2 路、最多 4 路，失败退避最低为 2；缓存窗口已满、到达文件末尾或用户禁用预取时，实际请求数按可下载任务决定。
- Android / TV 分离播放与预取的数据源：播放不等待预取缓存锁，缓冲时保留最近的预取任务；当前段连接 / 读取停滞采用限时、有上限的续拉。取消通过 HTTP 调用传递，缓存写入器由原工作线程关闭。
- Windows / macOS 按收到的数据立即写入、交付前缀；当前字节缺口久等时取消慢任务，从缺失偏移补拉，已成功的后段继续复用。已写入量与剩余预留量合计受原缓存预算约束。
- iOS 优先读取已到达的缓存前缀，每次写入唤醒等待者；被播放追上的预取请求提权，暂停远处预取并保留其前缀；停滞后从实际已接收偏移续拉，响应头只交付一次。
- 新增 Dart 慢头段 / 前缀交付 / 补拉上限、Android 预取让路 / 取消竞争、Swift 提权续拉 / 前缀读取回归。详细策略见 [下载说明](playback-downloads.md)。版本 `2.0.5+25`，沿用现有正式签名；仍需真机验证实际 CDN 的连续播放表现。

## 2.0.6 缓存条、手势反馈和 Android 交互修复

- Android 缓存原来按碎片逐个上报、逐个画圆角短线，密集相邻碎片会呈现点状。现在先按字节合并真实相邻 / 重叠区间，再转换时间；Flutter 同样合并解码缓冲与磁盘区间后绘制，保留实际空洞。iOS 原生 RangeStore 已合并相邻区间，本次补充相邻 / 淘汰空洞检查，共用绘制逻辑也同步防护。
- 手机左右侧竖滑分别显示亮度 / 音量的图标、百分比及动画进度条，控件隐藏时仍可见，松手后淡出。按起始值和累计位移计算目标，避免小幅音量移动逐次取整丢失；亮度改为发送绝对目标值，Android / iOS 均回传当前亮度。
- 手势反馈独立刷新，原生调节每 40ms 合并为最新目标，各类调节最多一路在途，松手补发最终值。横滑显示位置预览，松手只定位一次，避免每个移动事件都取消 / 重建下载任务；锁定时禁用调节。
- Android 缓存监听仅标记区间变化，排序 / 合并在预取后台线程至多每 500ms 执行，UI 只读内存快照。原生状态突发合并为一次事件，亮度 / 音量调节不再触发完整状态扫描；系统媒体元数据仅变化时更新，进度按秒更新。iOS 也减少调节导致的完整状态与系统媒体信息刷新。
- 回归覆盖密集缓存条的实际像素、真实空洞、Android / iOS 手势反馈与锁定、小位移精度、命令积压、视频视图重建次数及原生区间合并。版本 `2.0.6+26`，沿用现有正式签名；仍需在实际设备复验帧率、触摸跟手程度和系统亮度 / 音量效果。

## 2.0.7 首页全面屏铺满

- 首页不再由 Flutter 把 WebView 整体缩进安全区（刘海 / 灵动岛 / 手势条处会表现为上下黑边）。WebView 现在铺满整个窗口，Flutter 把当前方向的安全区通过 `--safe-top / --safe-right / --safe-bottom / --safe-left` 注入页面。
- 网页顶栏、底部导航和登录 / 初始化页改用这些变量：背景延伸到状态栏与手势条区域，只有文字和按钮避让；浏览器 / PWA 打开时回退到 `env(safe-area-inset-*)`。
- 横屏左右挖孔由 `safe-x` 处理。播放器仍是整窗视频、控件按安全区避让，不受影响。
- 版本 `2.0.7+27`。

## 2.0.8 画面比例设置与顶部安全区兜底

- 控制栏新增「画面比例」入口（播放器抽屉里的「画面」页），可选：原比例、铺满屏幕（裁剪）、拉伸铺满（变形，iOS 无此项）、16:9、4:3、21:9。选择写入配置，下次播放沿用。
- 桌面（media_kit）由 Flutter 计算画面矩形：裁剪 = 超出视口的居中矩形 + 裁剪，拉伸 = 保持视频比例后再非等比缩放，固定画幅 = 在该比例的框内保持视频原比例。
- Android 的裁剪 / 拉伸走 ExoPlayer 的 `resizeMode`（ZOOM / FILL），iOS 的铺满走 KSPlayer 的 aspect-fill，都由原生在知道视频尺寸的前提下完成，Flutter 不再叠加布局；固定画幅三端一致由 Flutter 布局。
- 顶部安全区改为取「外壳注入值」与 `env(safe-area-inset-*)` 的较大者（`--safe-*-inset` + `max()`），并在 `document-start` 就写入，避免注入晚一拍或 WebView 把 `env()` 报成 0 时顶栏按钮落到灵动岛 / 刘海下面。
- 版本 `2.0.8+28`。

## 2.0.9 首页顶部不再依赖网页安全区，播放器默认沉浸式

- 手机端 WebView 现在由 Flutter 自己避让顶部与左右安全区，底部仍然铺满并交给页面处理手势条。服务器上的前端即使还是旧版、完全不认识注入变量，首页顶栏按钮也不会再落到摄像头 / 灵动岛下面。
- `document-start` 注入同时覆盖 `.safe-top` 与 `.safe-x` 的 padding，避免新版页面在壳层已经避让后再次留白；`.safe-bottom` 仍由页面自行处理。
- 进入播放页立即隐藏系统状态栏与导航栏，控制栏、视频画面真正铺满整块屏幕；全屏按钮只负责再锁定横屏，退出全屏时保持沉浸式，退出播放器后恢复系统栏和方向。
- Android / iOS 播放状态补报 `video_width` / `video_height`，固定画幅（16:9、4:3、21:9）和桌面端一致使用真实视频尺寸。
- 版本 `2.0.9+29`。

## 2.0.10 播放异常不再清空进度

- 播放器重新装载、切换片源或报错时会把位置临时归零，旧逻辑会把这个 0 当成用户进度写回服务端，导致一次网络错误后续播点被清空。现在加载中、错误状态下不再上报位置，0 也不会覆盖已有的正数进度。
- 重试从出错前的最后位置继续，而不是回到打开播放器时的续播点。
- 进度队列会丢弃旧版本遗留的 `position_ms=0, finished=false` 快照；服务端同样忽略这类请求，保护所有客户端（Flutter、网页、companion）的已有进度。明确的「标记未看」仍可清零。
- 版本 `2.0.10+30`。

## 2.0.11 移动端「铺满屏幕」统一由 Flutter 裁剪

- 之前 Android 的 crop 交给 ExoPlayer `resizeMode`、iOS 交给 KSPlayer aspect-fill，部分设备上仍按 fit 渲染，横屏时左右留下黑边。现在移动端原生始终使用 FIT，Flutter 的 `VideoFrame` 按真实视频尺寸把平台视图放大到覆盖视口并裁掉溢出部分，保证「铺满屏幕（裁剪）」一定填满。
- Android 的「拉伸铺满」仍使用原生 `RESIZE_MODE_FILL`；其余画幅模式（原比例、裁剪、16:9、4:3、21:9）由 Flutter 统一布局，和桌面端一致，也避免原生与 Flutter 双重裁剪。
- 原生 `aspectFill` / `scale` 命令保留但不再接收 crop，避免旧播放会话残留裁剪状态。
- 版本 `2.0.11+31`。

## 2.0.12 播放启动反馈、选集定位与倍速保持

- 点击播放后立即显示「正在打开播放器…」全屏遮罩，不再等 `/api/play` 返回后主页才发生变化。
- API 客户端改为复用同一个 `HttpClient`，播放前的连续请求不再重复做 TCP/TLS 握手；只有配置了账号级播放覆盖且当前账号未知时才刷新 `/api/auth/state`。
- 课程 / 家庭视频没有季集号时，选集按播放列表序号显示 `P01`、`P02`，不再全部显示 `P00`；上千条选集改为懒加载列表，并在打开时自动定位到当前集。
- 连播切集继续使用遮罩避免闪回主页；已保存的常规倍速会在每个新播放页恢复。
- 版本 `2.0.12+32`。
